PHASE 2: IMAGE PROCESSING CORRECTNESS + SECURITY
============================================================

These are important.

------------------------------------------------------------
14. FIX EXIF ORIENTATION
------------------------------------------------------------

Current bug:

Image dimensions are read before:

ImageOps.exif_transpose()

This is incorrect for phone photos with EXIF orientation.

Correct order:

1. Decode image header
2. Read format
3. Apply EXIF transpose
4. Read final width/height
5. Validate pixel budget
6. Resize if necessary
7. Convert color space
8. Encode normalized image

The aspect ratio must be calculated AFTER EXIF orientation.

This is especially important for:

- phone photos
- portrait images
- Midjourney aspect ratios
- collage panel detection

Add a regression test with an EXIF-rotated test image.

Expected:

final normalized width/height reflects visual orientation.

------------------------------------------------------------
15. FIX TRANSPARENT PNG HANDLING
------------------------------------------------------------

Current behavior converts RGBA PNG directly to RGB.

This can expose arbitrary RGB data beneath transparent pixels.

Do not simply:

image.convert("RGB")

For images with alpha:

1. Create a deliberate background.
2. Composite RGBA over the background.
3. Then convert to RGB.

Use a neutral/white background appropriate for visual analysis.

Document the behavior.

Add a test for transparent PNG.

------------------------------------------------------------
16. FIX DECOMPRESSION-BOMB / PIXEL LIMIT
------------------------------------------------------------

Current max_image_pixels configuration is misleading.

It is being used as a dimension cap:

thumbnail((max_pixels, max_pixels))

It should represent an actual pixel budget.

Before fully decoding the image:

- inspect image dimensions
- calculate width * height
- reject if above the configured maximum

Do not call img.load() before validating the pixel budget.

Correct conceptual sequence:

open image
→ inspect dimensions
→ reject unreasonable dimensions
→ EXIF transpose
→ validate final dimensions
→ resize
→ load/decode
→ normalize

Avoid allocating enormous images before validation.

Add regression tests.

The error should be a controlled application error, not a process crash.

- decoded pixel limit

They protect against different attacks.

Make the configuration names explicit.

For example:

Do not silently change existing environment variable names unless backwards compatibility is maintained.

PHASE 3: URL FETCH SECURITY
============================================================

------------------------------------------------------------
18. STREAM IMAGE URL DOWNLOADS
------------------------------------------------------------

Current URL fetch downloads the entire response:

response.content

before checking size.

This allows a hostile server to stream an enormous response.

Change to streaming.

Conceptually:

client.stream(...)
→ inspect headers
→ reject obviously oversized Content-Length
→ read chunks
→ accumulate only until MAX_IMAGE_BYTES
→ abort immediately when exceeded

Do NOT buffer unbounded response bodies.

Use:

trust_env=False

so proxy environment variables cannot silently alter SSRF assumptions.

Preserve redirect limits.

------------------------------------------------------------
19. SSRF IP VALIDATION
------------------------------------------------------------

Current code manually blocks several private/reserved ranges.

This misses CGNAT:

100.64.0.0/10

Prefer a robust invariant based on Python IP semantics.

Conceptually:

if not ip.is_global:
    reject

Also handle:

- loopback
- private
- link-local
- reserved
- multicast
- unspecified
- CGNAT/non-public ranges

Apply validation to every redirect destination.

Do not assume validating only the initial URL is enough.

------------------------------------------------------------
20. DNS REBINDING HARDENING
------------------------------------------------------------

Current implementation:

resolve hostname
→ validate IP
→ make HTTP request by hostname

This has a TOCTOU DNS rebinding risk.

For production hardening:

resolve once
→ validate resolved addresses
→ connect using a pinned/validated IP
→ preserve the original Host header/SNI correctly

If the HTTP client architecture makes full pinning difficult, isolate this as a clearly documented residual risk rather than introducing a broken implementation.

Do not weaken current SSRF protections.

------------------------------------------------------------
21. ASYNC BLOCKING OPERATIONS
------------------------------------------------------------

PIL operations and socket.getaddrinfo can block the async event loop.

Where appropriate, move blocking work into:

asyncio.to_thread(...)

Do not prematurely parallelize everything.

Only move genuinely blocking operations.
